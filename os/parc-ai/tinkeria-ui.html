Explain how React reconciliation works in simple terms, with a small code example.

Think of React's reconciler as a diffing engine. Every time state changes, React builds a new tree of elements describing what the UI should look like, then compares it to the previous tree and figures out the minimum set of DOM mutations needed to match.

Why not just rebuild the DOM?

Directly rebuilding the whole DOM on every change is slow. So React does a lightweight comparison with a few key assumptions:

  • Different types unmount. If the element type changes (e.g. <div> becomes <span>), React tears down the subtree and rebuilds it.
  • Same type update in place. It keeps the same component instance and reconciles props down to the leaves.
  • key identity lets React track items across re-renders, so list items are recycled instead of recreated.

Here's the minimal shape of that process:

function render(rootEl, nextVNode) {
  const oldVNode = rootEl._vnode;

  // different type  replace whole subtree
  if (!oldVNode || oldVNode.type !== nextVNode.type) {
    rootEl.innerHTML = '';
    oldVNode = null;
  }

  diffChildren(rootEl, oldVNode, nextVNode);
  rootEl._vnode = nextVNode;
  return rootEl;
}

The key insight: React never touches nodes that didn't change. That narrow diff is why updates stay fast even in large apps.
